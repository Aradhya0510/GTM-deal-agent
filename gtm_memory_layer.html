Addendum · Stateful Agents

Memory layer for the
GTM Deal Intelligence Agent

The current implementation starts fresh on every invocation. This addendum adds two-tier stateful memory backed by Lakebase: short-term session checkpointing so AEs can have natural multi-turn conversations, and long-term cross-session memory so the agent gets smarter with every interaction.

The memory gap

Without memory, every agent invocation is isolated. Here's what that costs the GTM team in practice:

ScenarioWithout memoryWith memory
AE asks "make it shorter" Agent has no idea what to shorten — fails or hallucinates a new draft Short-term checkpoint recalls the prior outreach draft in the same session
AE mentions "Acme's champion changed" Gone next session — rep must repeat context every time Long-term memory extracts and stores the insight; surfaced on next Acme query
"I always want emails under 150 words" Preference lost between sessions; agent ignores stated style AE profile stores preferences; injected into every new session prompt
Mid-conversation deal pivot Cannot backtrack; must restart the entire conversation LangGraph time travel branches from any prior checkpoint without losing history
RevOps analyzing agent decisions No audit trail of what context was available at decision time Full checkpoint history in Lakebase; queryable via SQL for audit/debugging

Memory architecture

Two tiers, both backed by Lakebase. Short-term uses LangGraph's native CheckpointSaver wired to a Lakebase Postgres instance. Long-term uses a memory extraction agent that runs at session end and writes structured facts to UC-governed tables.

⚡
Short-term memory
Scoped to one conversation session
  • Persists every LangGraph node state to Lakebase via CheckpointSaver
  • Keyed by thread_id — one thread per conversation
  • AE can ask follow-up questions with full prior context
  • Time travel: branch from any prior checkpoint without losing original
  • Playground & Review App auto-pass thread_id via ChatContext
  • Survives agent restarts — state is durable in Postgres, not in-process
🧠
Long-term memory
Persists across all sessions, per AE
  • Memory extraction agent runs at session close, distills key facts
  • Three stores: AE preferences, account context, deal decisions
  • Retrieved at session start and injected into the system prompt
  • UC row-level security: AEs only see their own memories
  • Shared account context visible to all AEs on the same account
  • Memory ages out — recent facts weighted higher in retrieval

Session lifecycle with memory

1
Session start
Generate thread_id. Load AE long-term profile + account context from Lakebase.
2
Prompt inject
Prepend long-term memories to system prompt. AE preferences + recent account notes always in context.
3
Conversation
Each LangGraph step checkpointed to Lakebase. Multi-turn works natively via thread_id.
4
Session close
Memory extraction agent distills: preferences, deal insights, account context. Upserts to long-term store.
5
Next session
Improved
Long-term store has grown. Agent knows the AE, knows the account. Smarter from day one.
Databricks docs

When using the AI Playground or Review App, conversation_id and user_id are automatically passed as ChatContext — no manual thread_id wiring needed for those surfaces. For the Databricks Apps AE interface, pass thread_id explicitly via custom_inputs.

1 Lakebase memory schema

Three tables for long-term memory sit alongside the LangGraph checkpoint tables that Databricks manages automatically.

SQLmemory/00_schema.sql
-- Lakebase (Postgres) — same instance as the CRM operational store
-- LangGraph checkpoint tables are created automatically by CheckpointSaver.
-- We add three tables for long-term memory.

-- ── 1. AE preference profile ──────────────────────────────────────────
-- Stores persistent preferences extracted from conversations.
CREATE TABLE IF NOT EXISTS gtm.memory.ae_profiles (
  ae_id              VARCHAR PRIMARY KEY,
  email_style        JSONB,     -- {"max_words": 150, "tone": "direct", "avoid": ["jargon"]}
  outreach_prefs     JSONB,     -- {"preferred_cta": "15-min call", "follow_up_cadence": "3d"}
  avoid_competitors  VARCHAR[], -- Competitors the AE prefers not to mention
  formatting_prefs   JSONB,     -- {"bullet_points": false, "sign_off": "Best, Jamie"}
  raw_preferences    TEXT[],    -- Verbatim extracted preference statements
  updated_at         TIMESTAMP DEFAULT NOW()
);

-- ── 2. Account-level cross-session context ────────────────────────────
-- Shared across all AEs on the same account (with UC policy).
-- Captures deal nuances the agent has learned over multiple sessions.
CREATE TABLE IF NOT EXISTS gtm.memory.account_context (
  account_id         VARCHAR,
  context_type       VARCHAR,   -- 'champion_change' | 'budget_freeze' | 'competitor_mentioned'
  content            TEXT,      -- Human-readable fact, e.g. "Champion changed from Sarah to Mike (VP Eng) in Feb 2026"
  source_thread_id   VARCHAR,   -- Which conversation this came from
  ae_id              VARCHAR,   -- Who surfaced it
  confidence         FLOAT,     -- Extraction confidence 0-1
  extracted_at       TIMESTAMP DEFAULT NOW(),
  expires_at         TIMESTAMP, -- Optional TTL for stale facts
  PRIMARY KEY (account_id, context_type, extracted_at)
);

-- ── 3. Deal decision log ──────────────────────────────────────────────
-- Tracks what recommendations were made and whether AEs acted on them.
-- Feeds back into the Quotient AI RL loop.
CREATE TABLE IF NOT EXISTS gtm.memory.deal_decisions (
  decision_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  opp_id             VARCHAR,
  ae_id              VARCHAR,
  session_thread_id  VARCHAR,
  recommendation     TEXT,      -- What the agent recommended
  ae_action          VARCHAR,   -- 'accepted' | 'modified' | 'rejected'
  ae_feedback        TEXT,      -- Optional AE note on why they modified/rejected
  outcome            VARCHAR,   -- Populated later: 'deal_won' | 'deal_lost' | 'stalled'
  decided_at         TIMESTAMP DEFAULT NOW()
);

-- Index for fast AE-level retrieval
CREATE INDEX ON gtm.memory.account_context (account_id, extracted_at DESC);
CREATE INDEX ON gtm.memory.ae_profiles (ae_id);
CREATE INDEX ON gtm.memory.deal_decisions (opp_id, decided_at DESC);

2 Short-term memory — LangGraph checkpointing

Wire the Lakebase CheckpointSaver into the LangGraph graph. Every node execution writes a durable checkpoint — session continuity survives restarts, scales horizontally, and is fully auditable.

Pythonmemory/01_short_term.py
import uuid
import mlflow
from typing import Generator, Optional
from langgraph.graph import StateGraph, END
from databricks.agents.lakebase import CheckpointSaver
from databricks.agents import ResponsesAgentRequest, ResponsesAgentResponse
from databricks.agents import ResponsesAgentStreamEvent, LangGraphResponsesAgent

# ── Configuration ─────────────────────────────────────────────────────
LAKEBASE_INSTANCE = "gtm-memory"   # Your Lakebase instance name
LAKEBASE_SCHEMA   = "gtm.memory"   # Schema where checkpoint tables live


class GTMDealAgent(LangGraphResponsesAgent):
    """
    Stateful GTM Deal Intelligence Agent.
    Short-term memory: LangGraph checkpoints persisted to Lakebase.
    Long-term memory: Injected into system prompt at session start.
    """

    def _create_graph(self, checkpointer):
        """Build the LangGraph graph wired to the Lakebase checkpointer."""
        workflow = StateGraph(DealState)

        workflow.add_node("load_memory",  self._load_long_term_memory)
        workflow.add_node("research",     research_agent)
        workflow.add_node("scoring",      scoring_agent)
        workflow.add_node("outreach",     outreach_agent)
        workflow.add_node("save_memory",  self._trigger_memory_extraction)

        workflow.set_entry_point("load_memory")
        workflow.add_edge("load_memory", "research")
        workflow.add_edge("research",    "scoring")
        workflow.add_edge("scoring",     "outreach")
        workflow.add_edge("outreach",    "save_memory")
        workflow.add_edge("save_memory", END)

        # Wire in the Lakebase checkpoint saver
        return workflow.compile(checkpointer=checkpointer)

    # ── Prediction (non-streaming) ────────────────────────────────────
    def predict(self, request: ResponsesAgentRequest) -> ResponsesAgentResponse:
        custom_inputs = dict(request.custom_inputs or {})

        # Generate a new thread_id if this is a fresh conversation
        if "thread_id" not in custom_inputs:
            custom_inputs["thread_id"] = str(uuid.uuid4())
        request.custom_inputs = custom_inputs

        outputs = [
            event.item
            for event in self.predict_stream(request)
            if event.type == "response.output_item.done"
        ]

        # Surface thread_id and checkpoint_id in response for the App to store
        custom_outputs = {"thread_id": custom_inputs["thread_id"]}
        try:
            history = self.get_checkpoint_history(custom_inputs["thread_id"], limit=1)
            if history:
                custom_outputs["checkpoint_id"] = history[0]["checkpoint_id"]
        except Exception:
            pass

        return ResponsesAgentResponse(output=outputs, custom_outputs=custom_outputs)

    # ── Streaming prediction ──────────────────────────────────────────
    def predict_stream(
        self, request: ResponsesAgentRequest
    ) -> Generator[ResponsesAgentStreamEvent, None, None]:
        custom_inputs = request.custom_inputs or {}
        thread_id     = custom_inputs.get("thread_id", str(uuid.uuid4()))
        checkpoint_id = custom_inputs.get("checkpoint_id")  # for time-travel branching

        checkpoint_config = {"configurable": {"thread_id": thread_id}}
        if checkpoint_id:
            checkpoint_config["configurable"]["checkpoint_id"] = checkpoint_id

        # Open a connection-pooled Lakebase CheckpointSaver
        with CheckpointSaver(
            instance_name=LAKEBASE_INSTANCE,
            schema_name=LAKEBASE_SCHEMA
        ) as checkpointer:
            graph  = self._create_graph(checkpointer)
            inputs = self.prep_msgs_for_cc_llm([i.model_dump() for i in request.input])

            for event in graph.stream(
                {"messages": inputs, "thread_id": thread_id, "ae_id": custom_inputs.get("ae_id")},
                config=checkpoint_config,
                stream_mode="values"
            ):
                yield from self._convert_to_stream_events(event)

    # ── Checkpoint history (for time travel) ─────────────────────────
    def get_checkpoint_history(self, thread_id: str, limit: int = 10):
        config = {"configurable": {"thread_id": thread_id}}
        with CheckpointSaver(instance_name=LAKEBASE_INSTANCE, schema_name=LAKEBASE_SCHEMA) as cp:
            graph   = self._create_graph(cp)
            history = []
            for state in graph.get_state_history(config):
                if len(history) >= limit:
                    break
                history.append({
                    "checkpoint_id":  state.config["configurable"]["checkpoint_id"],
                    "thread_id":      thread_id,
                    "timestamp":      state.created_at,
                    "next_nodes":     state.next,
                    "message_count":  len(state.values.get("messages", [])),
                    "last_message":   (state.values.get("messages") or [""])[-1]
                })
        return history


# Register with MLflow
AGENT = GTMDealAgent()
mlflow.models.set_model(AGENT)
What checkpointing gives you for free

Every node execution is durably written to Lakebase. When an AE asks "make it shorter" in the same session, the agent retrieves the prior outreach draft from the checkpoint — no re-retrieval, no re-computation. The checkpoint also stores tool call results, so repeated queries within a session don't re-hit Salesforce or Gong.

3 Long-term memory — extraction & retrieval

A lightweight extraction agent runs at session close, distilling facts into the three Lakebase memory tables. At session start, relevant facts are retrieved and injected into the system prompt.

Memory extraction (session close)

Pythonmemory/02_extraction.py
import json
from databricks.sdk import WorkspaceClient
from databricks.agents import create_agent_executor

w  = WorkspaceClient()

# ── Memory extraction agent ───────────────────────────────────────────
# Runs once per session close. Reads the full conversation, extracts facts.
EXTRACTION_PROMPT = """
You are a memory extraction specialist for a GTM sales AI system.

Given a full conversation between a sales AE and a deal intelligence agent,
extract ONLY concrete, reusable facts. Do not extract vague or obvious statements.

Return a JSON object with three keys:

"ae_preferences": A list of AE-specific preferences discovered.
  Each item: {"preference_type": str, "value": str, "confidence": 0-1}
  Examples:
    {"preference_type": "email_max_words", "value": "150", "confidence": 0.95}
    {"preference_type": "avoid_competitor", "value": "Salesforce", "confidence": 0.90}
    {"preference_type": "preferred_cta", "value": "15-minute discovery call", "confidence": 0.85}

"account_context": A list of account-specific insights surfaced by the AE.
  Each item: {"account_id": str, "context_type": str, "content": str, "confidence": 0-1}
  Examples:
    {"account_id": "ACC-4821", "context_type": "champion_change",
     "content": "Champion changed from Sarah Chen (VP Sales) to Mike Torres (VP Eng) in Feb 2026",
     "confidence": 0.95}
    {"account_id": "ACC-4821", "context_type": "budget_freeze",
     "content": "Q1 budget frozen; revisit in April. CFO driving the decision.",
     "confidence": 0.90}

"deal_decisions": A list of recommendations the AE accepted, modified, or rejected.
  Each item: {"opp_id": str, "recommendation": str, "ae_action": str, "ae_feedback": str}

Return ONLY valid JSON. No preamble or explanation.
"""

memory_extractor = create_agent_executor(
    model="databricks/claude-3-5-haiku",  # Fast, cheap — runs at session close
    system_prompt=EXTRACTION_PROMPT
)


def extract_and_store_memories(thread_id: str, ae_id: str, conversation_history: list):
    """
    Called at session close. Extracts facts and upserts to Lakebase memory tables.
    Runs asynchronously so it doesn't block the AE's session close.
    """
    # Format conversation for extraction
    conversation_text = "\n".join([
        f"{m['role'].upper()}: {m['content']}"
        for m in conversation_history
        if m.get("content")
    ])

    result = memory_extractor.predict({
        "messages": [{"role": "user", "content": f"Extract memories from:\n\n{conversation_text}"}]
    })

    try:
        extracted = json.loads(result["messages"][-1]["content"])
    except json.JSONDecodeError:
        return  # Extraction failed; log and skip silently

    conn = w.lakebase.connect(instance_name="gtm-memory")

    # ── Upsert AE preferences ────────────────────────────────────────
    for pref in extracted.get("ae_preferences", []):
        if pref["confidence"] < 0.75:
            continue  # Skip low-confidence extractions
        conn.execute("""
            INSERT INTO gtm.memory.ae_profiles (ae_id, raw_preferences, updated_at)
            VALUES (%s, ARRAY[%s::TEXT], NOW())
            ON CONFLICT (ae_id) DO UPDATE SET
              raw_preferences = array_append(ae_profiles.raw_preferences, EXCLUDED.raw_preferences[1]),
              updated_at = NOW()
        """, [ae_id, f"{pref['preference_type']}:{pref['value']}"])

    # ── Upsert account context ───────────────────────────────────────
    for ctx in extracted.get("account_context", []):
        if ctx["confidence"] < 0.80:
            continue
        conn.execute("""
            INSERT INTO gtm.memory.account_context
              (account_id, context_type, content, source_thread_id, ae_id, confidence, extracted_at)
            VALUES (%s, %s, %s, %s, %s, %s, NOW())
        """, [ctx["account_id"], ctx["context_type"], ctx["content"], thread_id, ae_id, ctx["confidence"]])

    # ── Log deal decisions ───────────────────────────────────────────
    for dec in extracted.get("deal_decisions", []):
        conn.execute("""
            INSERT INTO gtm.memory.deal_decisions
              (opp_id, ae_id, session_thread_id, recommendation, ae_action, ae_feedback)
            VALUES (%s, %s, %s, %s, %s, %s)
        """, [dec["opp_id"], ae_id, thread_id, dec["recommendation"], dec["ae_action"], dec.get("ae_feedback", "")])

Memory retrieval (session start)

Pythonmemory/03_retrieval.py
from datetime import datetime, timedelta

def load_long_term_memory(ae_id: str, account_id: str = None) -> dict:
    """
    Called at session start. Retrieves AE profile and account context.
    Returns a structured memory object to inject into the system prompt.
    """
    conn = w.lakebase.connect(instance_name="gtm-memory")

    # ── AE preferences ───────────────────────────────────────────────
    ae_prefs = conn.execute("""
        SELECT email_style, outreach_prefs, avoid_competitors,
               formatting_prefs, raw_preferences
        FROM gtm.memory.ae_profiles
        WHERE ae_id = %s
    """, [ae_id]).fetchone()

    # ── Account context (last 90 days, confidence > 0.80) ────────────
    account_context = []
    if account_id:
        account_context = conn.execute("""
            SELECT context_type, content, ae_id, confidence, extracted_at
            FROM gtm.memory.account_context
            WHERE account_id = %s
              AND extracted_at > NOW() - INTERVAL '90 days'
              AND confidence > 0.80
            ORDER BY extracted_at DESC
            LIMIT 10
        """, [account_id]).fetchall()

    # ── Recent deal decisions on this account ────────────────────────
    recent_decisions = []
    if account_id:
        recent_decisions = conn.execute("""
            SELECT d.recommendation, d.ae_action, d.ae_feedback, d.decided_at
            FROM gtm.memory.deal_decisions d
            JOIN gtm.opportunities o ON d.opp_id = o.opp_id
            WHERE o.account_id = %s
              AND d.decided_at > NOW() - INTERVAL '30 days'
            ORDER BY d.decided_at DESC
            LIMIT 5
        """, [account_id]).fetchall()

    return {
        "ae_preferences":   ae_prefs,
        "account_context":  account_context,
        "recent_decisions": recent_decisions
    }


def build_memory_system_prompt(ae_id: str, account_id: str = None) -> str:
    """
    Constructs the memory prefix injected at the top of every system prompt.
    Keeps it concise — only high-signal facts that change agent behavior.
    """
    memory = load_long_term_memory(ae_id, account_id)
    sections = []

    # AE preferences
    if memory["ae_preferences"]:
        prefs = memory["ae_preferences"]
        pref_lines = []
        if prefs.get("email_style", {}).get("max_words"):
            pref_lines.append(f"- Keep emails under {prefs['email_style']['max_words']} words")
        if prefs.get("avoid_competitors"):
            pref_lines.append(f"- Do not mention: {', '.join(prefs['avoid_competitors'])}")
        if prefs.get("raw_preferences"):
            for p in (prefs["raw_preferences"] or [])[-5:]:  # Last 5 stated preferences
                pref_lines.append(f"- {p.split(':', 1)[-1]}")
        if pref_lines:
            sections.append("## AE PREFERENCES (from prior sessions)\n" + "\n".join(pref_lines))

    # Account context
    if memory["account_context"]:
        ctx_lines = [
            f"- [{row['context_type']}] {row['content']} (surfaced {row['extracted_at'].strftime('%b %Y')})"
            for row in memory["account_context"]
        ]
        sections.append("## ACCOUNT CONTEXT (from prior sessions)\n" + "\n".join(ctx_lines))

    # Recent decisions
    if memory["recent_decisions"]:
        dec_lines = [
            f"- Recommended: \"{row['recommendation'][:80]}...\" → AE {row['ae_action']}"
            + (f": \"{row['ae_feedback']}\"" if row['ae_feedback'] else "")
            for row in memory["recent_decisions"]
        ]
        sections.append("## RECENT DECISION HISTORY\n" + "\n".join(dec_lines))

    if not sections:
        return ""  # No prior memory — clean first session

    return (
        "# MEMORY FROM PRIOR SESSIONS\n"
        "The following was learned from previous conversations. Apply it silently.\n\n"
        + "\n\n".join(sections)
        + "\n\n---\n\n"
    )

4 Updated LangGraph with memory nodes

Add load_memory as the entry node and save_memory as the exit node. The rest of the graph from Phase 4 is unchanged.

Pythonmemory/04_graph_update.py
from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

class DealState(TypedDict):
    messages:          Annotated[list, operator.add]
    thread_id:         str
    ae_id:             str
    account_id:        str
    opp_id:            str
    # ── Memory fields (new) ──────────────────────────────────────────
    memory_prefix:     str          # Long-term memory injected into system prompt
    session_summary:   str          # Filled by save_memory node at exit
    # ── Agent outputs (unchanged from Phase 4) ───────────────────────
    deal_health:       dict
    account_signals:   dict
    outreach_draft:    str
    risk_flags:        list


# ── Memory nodes ─────────────────────────────────────────────────────

def load_memory_node(state: DealState) -> DealState:
    """
    Entry node: load long-term memory and inject into agent context.
    Runs once per session start — lightweight Lakebase read.
    """
    memory_prefix = build_memory_system_prompt(
        ae_id=state["ae_id"],
        account_id=state.get("account_id")
    )
    # Prepend memory to the system message in the conversation
    if memory_prefix and state["messages"]:
        first_msg = state["messages"][0]
        if first_msg.get("role") == "system":
            state["messages"][0]["content"] = memory_prefix + first_msg["content"]
        else:
            state["messages"].insert(0, {"role": "system", "content": memory_prefix})

    return {"memory_prefix": memory_prefix, "messages": state["messages"]}


def save_memory_node(state: DealState) -> DealState:
    """
    Exit node: trigger async memory extraction. Non-blocking.
    The session response is already returned to the AE; extraction runs in background.
    """
    import threading
    t = threading.Thread(
        target=extract_and_store_memories,
        args=(state["thread_id"], state["ae_id"], state["messages"]),
        daemon=True
    )
    t.start()
    return {}  # No state change needed — extraction is async


# ── Updated graph ─────────────────────────────────────────────────────

def build_gtm_graph(checkpointer):
    workflow = StateGraph(DealState)

    # Memory bookend nodes (new)
    workflow.add_node("load_memory",  load_memory_node)
    workflow.add_node("save_memory",  save_memory_node)

    # Core agent nodes (unchanged from Phase 4)
    workflow.add_node("research",     research_agent)
    workflow.add_node("scoring",      scoring_agent)
    workflow.add_node("outreach",     outreach_agent)

    # Flow: memory → core agents → memory
    workflow.set_entry_point("load_memory")
    workflow.add_edge("load_memory", "research")
    workflow.add_edge("research",    "scoring")
    workflow.add_edge("scoring",     "outreach")
    workflow.add_edge("outreach",    "save_memory")
    workflow.add_edge("save_memory", END)

    return workflow.compile(checkpointer=checkpointer)

5 Time travel — branching deal conversations

An AE approved a follow-up angle, then changed their mind. Time travel lets them fork the conversation from any prior checkpoint without losing the original thread.

GTM scenario

AE generates an outreach email, then realizes they want to try a completely different angle (product-led vs. ROI-led). Instead of starting over, they branch from the checkpoint just before the outreach node and try again — both branches preserved in Lakebase.

Pythonmemory/05_time_travel.py
# ── GTM time travel example ───────────────────────────────────────────

# 1. Start a session about Acme Corp
response1 = AGENT.predict({
    "input": [{"role": "user",
               "content": "Analyze OPP-4821 (Acme Corp) and draft a follow-up email focused on ROI."}],
    "custom_inputs": {"ae_id": "ae-jamie-torres"}
})
thread_id = response1.custom_outputs["thread_id"]
print(f"Session thread: {thread_id}")
print(response1)

# 2. Continue in same thread — agent remembers OPP-4821 context
response2 = AGENT.predict({
    "input": [{"role": "user", "content": "Make the subject line punchier."}],
    "custom_inputs": {"thread_id": thread_id, "ae_id": "ae-jamie-torres"}
})

# 3. AE wants to try a completely different angle — inspect checkpoint history
history = AGENT.get_checkpoint_history(thread_id, limit=10)
print("Checkpoint history:")
for i, ckpt in enumerate(history):
    print(f"  [{i}] {ckpt['timestamp']} | next={ckpt['next_nodes']} | msgs={ckpt['message_count']}")

# 4. Branch from the checkpoint just before the outreach node ran
#    (find the checkpoint where next_nodes includes 'outreach')
branch_point = next(
    (h["checkpoint_id"] for h in history if "outreach" in str(h["next_nodes"])),
    history[-1]["checkpoint_id"]  # Fallback to oldest
)

# 5. Fork the conversation — try a product-led growth angle instead
response_fork = AGENT.predict({
    "input": [{"role": "user",
               "content": "Actually, try a product-led angle instead — lead with their usage data, not ROI metrics."}],
    "custom_inputs": {
        "thread_id":     thread_id,      # Same thread
        "checkpoint_id": branch_point,   # Branch from this checkpoint
        "ae_id":         "ae-jamie-torres"
    }
})
# Both branches (ROI-led and PLG-led) are now preserved in Lakebase.
# The AE can compare them side-by-side in the App UI.
branched_checkpoint = response_fork.custom_outputs["checkpoint_id"]
print(f"Original branch checkpoint: {branch_point}")
print(f"New fork checkpoint:        {branched_checkpoint}")
print(response_fork)

6 App layer — thread ID management

The Databricks Apps AE interface must persist thread_id client-side and pass it on every turn. This is the only AE-visible surface change.

Playground & Review App

When using the AI Playground or Review App, thread_id and user_id are passed automatically via ChatContext. No extra wiring needed for those surfaces — only the custom Databricks Apps UI requires manual thread_id management.

# Session state: persist thread_id across Streamlit reruns
if "thread_id" not in st.session_state:
    st.session_state.thread_id = None   # None = new session, agent will generate one
if "messages" not in st.session_state:
    st.session_state.messages = []

# ── "New conversation" button ────────────────────────────────────────
col1, col2 = st.columns([3, 1])
with col2:
    if st.button("New conversation"):
        st.session_state.thread_id = None
        st.session_state.messages  = []
        st.rerun()

# Display prior messages in this session
for msg in st.session_state.messages:
    with st.chat_message(msg["role"]):
        st.write(msg["content"])

# ── Chat input ────────────────────────────────────────────────────────
if prompt := st.chat_input("Ask about a deal, account, or generate outreach..."):
    st.session_state.messages.append({"role": "user", "content": prompt})

    with st.chat_message("user"):
        st.write(prompt)

    with st.chat_message("assistant"):
        placeholder = st.empty()

        # Pass thread_id so the agent checkpoints to the right session
        custom_inputs = {
            "ae_id": st.experimental_user.email,  # AE identity from SSO
        }
        if st.session_state.thread_id:
            custom_inputs["thread_id"] = st.session_state.thread_id

        # Stream the response
        full_response = ""
        stream = client.responses.create(
            model="gtm-deal-intelligence",   # Your Model Serving endpoint
            input=[{"role": "user", "content": prompt}],
            stream=True,
            extra_body={"custom_inputs": custom_inputs}
        )

        for chunk in stream:
            if chunk.type == "response.output_text.delta":
                full_response += chunk.delta
                placeholder.markdown(full_response + "▌")

        placeholder.markdown(full_response)

        # Persist thread_id returned by the agent (first turn generates it)
        if hasattr(stream, "custom_outputs") and stream.custom_outputs:
            st.session_state.thread_id = stream.custom_outputs.get(
                "thread_id", st.session_state.thread_id
            )

        st.session_state.messages.append({"role": "assistant", "content": full_response})

7 Governance for memory tables

AE preferences and deal decisions are personal data. Unity Catalog policies ensure AEs only see their own memories, while account context is appropriately shared within the account team.

SQLmemory/07_uc_memory_policy.sql
-- AE profiles: strictly personal — only the AE and managers
CREATE ROW FILTER gtm.security.ae_profile_filter
  ON gtm.memory.ae_profiles (ae_id VARCHAR)
  AS ae_id = CURRENT_USER()
  OR IS_MEMBER('sales-leadership');

ALTER TABLE gtm.memory.ae_profiles
  ADD ROW FILTER gtm.security.ae_profile_filter ON (ae_id);

-- Account context: shared across AEs on the same account team,
-- but restricted by territory (same policy as opportunities)
CREATE ROW FILTER gtm.security.account_context_filter
  ON gtm.memory.account_context (ae_id VARCHAR)
  AS EXISTS (
    SELECT 1 FROM gtm.accounts a
    WHERE a.account_id = account_context.account_id
      AND (a.ae_owner = CURRENT_USER() OR IS_MEMBER('sales-leadership'))
  );

ALTER TABLE gtm.memory.account_context
  ADD ROW FILTER gtm.security.account_context_filter ON (ae_id);

-- Deal decisions: visible to the AE and their manager
CREATE ROW FILTER gtm.security.decision_filter
  ON gtm.memory.deal_decisions (ae_id VARCHAR)
  AS ae_id = CURRENT_USER()
  OR IS_MEMBER('sales-leadership')
  OR IS_MEMBER('revenue-operations');

ALTER TABLE gtm.memory.deal_decisions
  ADD ROW FILTER gtm.security.decision_filter ON (ae_id);
